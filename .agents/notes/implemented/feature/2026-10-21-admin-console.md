# Agent Note: 管理后台与 C 端分家（admin-* 命名空间）

Status: implemented

## Problem

后台是给运营/自己用的内部工具，C 端是给用户看的水墨站。两者的目标冲突：C 端要留白、字距、诗意；后台要密度、扫读、一次看到 20 行。把后台塞进 `WorkspaceShell` 会让两套视觉互相污染——水墨的宽字距与 1px 细线在表格里会读不动，后台的白面板与等宽数字又会破坏 C 端的纸感。

## Decision

`/admin` 是**独立于 `WorkspaceShell` 的路由**，渲染自己的 `AdminPage`，配一套只属于自己的 `src/styles/admin.css`：

- 所有类名 `admin-` 前缀，不引用也不覆盖 `.ink-*` 与 `.workspace-*`；
- 样式在 `AdminPage.tsx` 内 `import '@/styles/admin.css'`，因此随路由懒加载——C 端用户永远不会下载后台 CSS；
- 视觉语言：纸色底 + 白面板、1px 边框、无圆角无阴影、数字等宽（`--admin-mono`）、表格行 7px 内边距、表头 sticky；
- 权限失败渲染成 **404 页面**（与接口的 404 行为一致），不显示"无权访问"，避免暴露后台存在性。

页面结构：概览（6 个计数）/ 用户（搜索、角色与状态操作）/ 订单 / 商品（新增与更新）/ 兑换码（生成与批次统计）/ 审计（写操作留痕）。

## Alternatives considered

1. **复用 `WorkspaceShell` + 水墨皮肤**：实现最省，但表格在水墨参数下不可读（行高偏大、字距过宽、强调色只有朱砂一档无法区分状态）。
2. **单独一个 Vite 工程**：隔离最彻底，但多一条构建链、多一套部署产物，单 SPA 用路由分隔已足够。
3. **引入现成后台框架（Ant Design Pro 等）**：组件齐全，但会带进一整套设计体系与依赖体积，与"水墨 C 端 + 极简后台"的取向冲突。
4. **权限失败提示"无权限"或跳登录**：更友好，但会告诉任何人这个路径存在后台。选择与接口一致的 404。

## Consequences

- 收益：两套视觉互不干扰；后台样式随路由分包，C 端首屏零成本；权限探测面收窄。
- 代价：后台没有复用 C 端的组件（按钮/输入框各写一套），后续若要统一交互成本更高——这是刻意接受的重复。
- 代价：后台页面之间用 React state 切 tab，没有 URL 路由，刷新会回到概览、也无法直接分享某一页；后续若需要深链接，要改成 `/admin/:tab`。
- 验证：`tsc` 通过；用 fixture 预览截图确认概览与用户表渲染正常（预览分支已移除，`grep PREVIEW` = 0）；接口侧此前已用 curl 全量验证（含非 admin → 404、停用即吊销会话、禁止自我降权）。
