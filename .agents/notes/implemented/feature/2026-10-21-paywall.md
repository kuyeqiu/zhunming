# Agent Note: 付费墙只锁 AI 解读

Status: implemented

## Problem

收费必须有闸门，但闸门放错位置会毁掉产品：把排盘/盘面锁住，会让"功能尽可能都有"直接失效，也会让首屏体验变差——而竞品恰恰是"功能全但难看"。同时闸门必须落在有边际成本的地方，否则收钱收得没有依据。

## Decision

**只锁一处：内置 AI 解读（`/api/v1/ai/analyze`）。排盘、盘面、历法、古籍全部免费。**

实现分三层：

1. **入口闸**（`server/docker-server.ts`）：在公共 API 分发之前拦 `/api/v1/ai/analyze`，未通过直接返回 `402`，body 形如
   `{ ok:false, error:{ code:'PAYWALL', message, used, limit, upgradeUrl:'/account' } }`，与既有 `aiJsonError` 的结构一致。
2. **判定**（`server/app/gate.ts`）：
   - `MINGYU_PAYWALL_ENABLED=false` 时整体放行（自部署逃生口）；
   - 会员（`entitlements` 里 `kind='membership'` 且未过期）不限次，但仍写用量流水，为将来按量计费留数据；
   - 其余按身份计：登录用户 `usr:<id>`，未登录 `ip:<sha256(ip)[:16]>`，每日额度 `MINGYU_FREE_AI_DAILY`（默认 3）；
   - 计数落在 `ai_usage`（v2 迁移新增 `identity` 列 + 索引），按自然日切分。
3. **展示**（`GET /api/app/access` + 账户页「今日解读」格）：返回 `tier / limit / used / remaining`，会员显示「无限」。

## Alternatives considered

1. **锁排盘入口**：转化最直接，但与"功能不删、只分层"和"好看优先"同时冲突，放弃。
2. **锁报告导出（PDF/长图）**：受众更窄、感知更弱，且导出功能还没做，无法先上线；留作后续第二个闸门。
3. **按次扣余额（credits）**：更精细，但需要先有充值与退款流程；当前用"会员不限次 + 免费日限"更简单可靠，余额体系保留在库里不启用。
4. **在客户端做拦截**（隐藏按钮 / 判断权益后不发请求）：体验最顺但毫无防护，任何人直接打接口即可绕过。服务端闸门是唯一可信位置。
5. **把闸门写在 `src/lib/ai/proxy.ts` 里**：那是上游代码，改它会让后续跟上游合并产生冲突；放在 server 外壳层可完全隔离。

## Consequences

- 收益：收费闭环在服务端成立，绕过不了；排盘免费面完整保留；上游 AI 代码零改动。
- 代价：请求失败（例如上游 AI 未配置、网络中断）也会消耗一次免费额度——因为用量在放行时先记。当前接受，后续可改为「成功后再记账」。
- 代价：`ai_usage` 用自然日切分，跨时区边界按服务器本地时间，多地区部署会出现口径差异。
- 未做：报告导出的第二个闸门；402 触发时前端还只是显示错误文案，缺少"开通会员"的引导卡片（UX 债，已记录）。
- 验证：`MINGYU_FREE_AI_DAILY=2` 下实测——匿名第 3 次请求返回 `402 PAYWALL`（`used:3, limit:2`）；兑换会员码后 `/api/app/access` 变 `tier:"member", limit:null`，同一接口不再返回 402。
