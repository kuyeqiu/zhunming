# Agent Note: 功能取舍——招牌六项 + 全部工具

Status: implemented

## Problem

新版核心包有 32 个术数能力，侧栏把所有工具平铺出来共 24 项（命盘 8 / 占问 14 / 择时 2）。对第一次来的用户，这是一堵墙：看不出该点哪个，也看不出哪些是"招牌"。产品定位是"不缺功能全的站，缺好看的站"，所以需要分层——**功能不删，只分层**。

## Decision

在 `src/lib/workspace.ts` 声明 `FEATURED_FEATURE_IDS`，作为唯一的取舍清单：

```ts
['bazi', 'ziwei', 'astrolabe', 'compatibility', 'liuyao', 'calendar']
```

筛选依据不是功能强弱，而是「第一次来最可能点的」：命盘看八字/紫微/星盘，关系看合盘，问事看六爻，择日看干支日历。

侧栏（`WorkspaceShell`）据此重排：

1. 顶部保留 首页 / 案例 / 文字与数理；
2. 新增「招牌」分组，按 `FEATURED_FEATURE_IDS` 顺序渲染 6 项；
3. 其余收进「＋ 全部工具（18）」一行，默认折叠，点击展开原有的 命盘 / 占问 / 择时 分组；
4. 分组渲染时过滤掉已出现在招牌里的项，避免重复；
5. 招牌与分组共用同一个 `renderFeatureButton`，防止两处按钮行为漂移。

## Alternatives considered

1. **删掉冷门工具**：最干净，但与"原站功能尽可能都有"直接冲突；太乙、皇极经世这类冷门项反而是差异化资产。
2. **只改首页、不动侧栏**：首页已有"排盘/占问/即时盘"三模式与选择弹窗，改首页对首屏观感提升有限，而侧栏是每一页都存在的墙。
3. **按使用频率动态排序**：更聪明，但需要先有行为埋点数据；当前用固定清单，数据够了再换。
4. **把全部工具做成独立页面（/tools）**：层级更清楚，但多一次跳转；折叠行在原地展开更轻。
5. **默认展开全部工具**：对老用户友好，但对新用户等于没有分层。选择默认折叠——首页仍提供完整入口。

## Consequences

- 收益：首屏只看到 6 个招牌，认知负担下降；全部工具仍一键可达，功能零删减。
- 代价：默认折叠让熟练用户多一次点击；若数据表明某工具被高频使用，需要回到 `FEATURED_FEATURE_IDS` 调整（清单集中在一处，改起来是一行）。
- 代价：`orderedFeatures.length - FEATURED_FEATURE_IDS.length` 的计数假设招牌项一定在全集内；若将来清单里写了不存在的 id，计数会偏大（当前 6 项都有效）。
- 未做：首页选择弹窗仍按分组平铺，没有同步分层；`WorkspaceSettingsModal` 里的排序功能仍作用于全部工具。
- 验证：`pnpm typecheck:app` 通过；首页截图确认「招牌」6 项 + 「＋ 全部工具（18）」折叠行；`pnpm build` exit 0。
